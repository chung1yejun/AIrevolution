# 디자인 규칙 (design.md)

담당: 정예준 작성 · 공통 부품 구현: 김수아(S2, S3)
기준 시안: 김수아 피그마 시안(공통 UI 부품, `/dev-ui`)의 색과 부품 + 정예준 첫 화면(`/`)의 화면 구성.

## 0. 방향
- **밤의 남색 위에 아이보리 종이.** 장례 이후에 쓰는 서비스라 화면은 어둡고 조용한 남색, 손에 쥐는 것(버튼, 카드, 입력칸)은 따뜻한 아이보리로 띄운다. 밝은 원색, 그림자, 이모지는 쓰지 않는다.
- **한 화면에 말 하나.** 큰 명조 제목 한두 줄 → 짧은 설명 한 줄 → 내용 → 맨 아래 큰 버튼 하나. 첫 화면이 이 모양의 기준이다.
- **기한은 세로 선으로.** 이 서비스의 핵심 정보는 '언제까지'다. 기한이 있는 목록은 첫 화면처럼 왼쪽 세로 선 + 동그라미로 이어 보여 준다(5장 Timeline). 남김을 알아보게 하는 장치는 이것 하나로 아끼고, 나머지는 조용하게 둔다.
- 하지 않는 것: 모든 내용을 같은 카드로 잘게 나누기, 제목 위 영어 대문자 꼬리표, 한 단어만 색 바꾸기, 버튼 글자 끝의 화살표(→), 'A · B · C'처럼 가운뎃점으로 잇는 설명줄, 섹션마다 나타나는 움직임.

## 1. 색 (`app/globals.css`의 `@theme`, Tailwind 이름으로 쓴다)
| 이름 | 값 | 쓰는 곳 |
|---|---|---|
| bg | `#19263C` (밤 남색) | 모든 이용자 화면 배경 |
| surface | `#2F3E56` (짙은 회남색) | 남색 위의 면: 보조 정보 묶음, 진행 막대 바탕, 'AI 생성' 태그 |
| primary | `#F5F1E9` (아이보리) | 주 버튼, 카드, 선택된 항목, 진행률 채움, 선택된 탭 |
| on-primary | `#19263C` | 아이보리 위의 글자 |
| text | `#F5F1E9` | 남색 위 제목·본문 |
| text-sub | `#AAB5C9` (안개 회청) | 남색 위 보조 설명, 비활성 버튼 바탕, '샘플' 태그 |
| border | `#2F3E56` | 구분선, 세로 기한 선 |
| field | `#E5E8ED` | 입력칸·선택 목록 바탕 |
| warn | `#F2C1B9` | 남색 위 오류·기한 임박 글자 |
| warn-ink | `#822F29` | 아이보리·입력칸 위 오류 글자와 테두리 |
| done | `#B9D3B6` | 완료 표시(남색 위) |
| stem | `#A9A093` | 국화 마크 줄기(장식 전용) |

- 글자 대비: 남색 위에는 text 또는 text-sub만, 아이보리·field 위에는 on-primary 또는 warn-ink만 쓴다.
- 흰색(`#FFFFFF`)과 검정은 쓰지 않는다. 가장 밝은 색은 아이보리, 가장 어두운 색은 bg.
- 배경은 평평한 남색 한 장이 아니라 위쪽이 아주 조금 밝다(`body`에 들어 있음: 위에서 `#22314B`로 시작해 bg로 스며듦). 따로 배경 그림이나 그라데이션을 더하지 않는다.

## 2. 글자
- **명조(제목용)**: Gowun Batang(고운바탕) 700. `font-serif` 클래스. 서비스 이름 '남김', 화면의 큰 제목(첫 화면, 질문, 각 화면 맨 위 제목)에만 쓴다.
- **고딕(나머지 전부)**: Pretendard. 기본 글꼴이라 따로 클래스가 필요 없다. Inter, Roboto, 시스템 기본 글꼴로 바꾸지 않는다.
- 크기와 줄 간격:

| 쓰임 | 크기 | 굵기 | 줄 간격 |
|---|---|---|---|
| 큰 제목(명조) | 30px | 700 | 1.45 |
| 화면 제목(명조) | 24px | 700 | 1.4 |
| 섹션 제목 | 18px | 700 | 1.4 |
| 항목 이름 | 17px | 700 | 1.4 |
| 본문 | 16px | 400 | 1.6 |
| 보조 | 14~15px | 400 | 1.5 |

- 제목과 문장은 `break-keep`(단어 중간에서 줄바꿈 안 함). 큰 제목은 두 줄 안으로, 생각 단위로 `<br />`를 넣어 끊는다.
- 숫자(D-day, 날짜, 건수)는 굵게, `tabular-nums`.
- 한 줄은 휴대폰 폭을 넘지 않으니 따로 줄 길이를 제한하지 않는다. 넓은 화면에서도 480px 틀 안.

## 3. 간격과 모양
- 간격은 4의 배수. 화면 좌우 여백 16px(`.mobile-frame`).
- 화면 구성 간격: 헤더 → 큰 제목 56px, 제목 → 설명 16px, 설명 → 내용 40px, 내용 → 아래 버튼 최소 40px.
- 모서리: 버튼·입력칸·카드 16px(`rounded-2xl`), 태그 알약 모양(`rounded-full`), 체크박스 5px. 떠 있는 메뉴만 16px + 옅은 그림자 허용.
- 테두리는 의미가 있을 때만: 보조 버튼(아이보리 1px), '전문가 확인 필요' 태그, 오류 입력칸(warn-ink 2px).
- 누르는 영역 최소 44px, 화면 아래 주 버튼 높이 56px.
- 키보드 초점은 항상 보이게: `outline: 2px solid text-sub`, 바깥으로 3px 띄움.

## 4. 화면 틀
첫 화면(`app/page.tsx`)을 기준으로 모든 이용자 화면을 같은 순서로 쌓는다.

```
┌──────────────────────────┐
│ 남김(명조)            ≡/← │  헤더 높이 44px: 왼쪽 서비스 이름 또는 뒤로가기, 오른쪽 메뉴·내 정보
│                          │
│ 큰 제목 한두 줄(명조 30)   │  화면이 하는 일 하나
│ 설명 한 줄(text-sub)      │
│                          │
│ 내용                      │  기한 목록 → Timeline, 입력 → Input/Select,
│                          │  여러 항목 → 구분선으로 나눈 목록(카드 남발 X)
│                          │
│ [ 주 버튼 아이보리 56px ]  │  맨 아래 고정이 아니라 내용 끝(margin-top: auto)
│      보조 링크(text-sub)   │
└──────────────────────────┘
```

- 폭 375px 기준, 넓은 화면에서는 최대 480px 가운데. 바깥도 같은 남색.
- 하단 탭(로그인 후): 높이 64px, 배경 bg, 위쪽 border 1px. 아이콘 + 글자 4개(홈, AI 분석, 서류, 맡기기). 선택된 탭 primary(아이보리), 나머지 text-sub. 내용이 탭에 가리지 않게 아래 여백.
- 긴 글 화면(`/about`)은 섹션 제목 + 본문을 구분선으로 나눈다. 섹션마다 카드로 감싸지 않는다.
- `/partner`는 PC 화면 최대 1200px, 숫자 4개를 한 줄에. 색은 같다.

## 5. 공통 부품 (`components/ui/`, `/dev-ui`에서 확인)
| 부품 | 규칙 |
|---|---|
| Button | `variant`: primary(아이보리 바탕 + 남색 글자) / secondary(남색 바탕 + 아이보리 1px 테두리) / ghost(테두리 없는 글자 버튼). 비활성은 text-sub 바탕. 높이 56px, 폭 100%, 누르는 중엔 `loading`으로 돌아가는 원 |
| Card | 아이보리 바탕, 남색 글자, 둥글기 16px, 안쪽 여백 20px. **한 화면에 꼭 짚어야 할 것(오늘 할 일, 결과 요약)에만** 쓴다 |
| Checkbox | 24px, 남색 바탕 + text-sub 테두리, 체크하면 아이보리 바탕 + 남색 체크. 글자까지 누를 수 있게 |
| ProgressBar | 높이 8px, 바탕 surface, 채움 primary. 옆에 "3/9 완료" |
| Tag | 알약 모양 14px. 샘플(text-sub 바탕 + 남색 글자) / AI 생성(surface 바탕 + 아이보리 글자) / 전문가 확인 필요(text-sub 테두리 + 아이보리 글자) / 기한 임박(아이보리 바탕 + warn-ink 글자) |
| Input, Select | 높이 56px, field 바탕, 남색 글자, 위에 굵은 라벨, 아래 오류 문구(warn). 오류면 아이보리 바탕 + warn-ink 2px 테두리 |
| Timeline | 첫 화면의 기한 흐름. 왼쪽 2px 세로 선(border 색), 항목마다 12px 동그라미(아이보리 2px 테두리, 안은 bg). 항목 이름 17px 굵게 + 아래 기한 15px text-sub. 끝난 항목은 동그라미를 아이보리로 채운다. 아직 공통 부품이 아니라 `app/landing.css`의 `.lp-timeline`에 있다 |
| Chrysanthemum | 국화 마크. 서비스 이름 옆이나 빈 화면에만, 장식으로(`aria-hidden`) |
| BottomTab | 4장 참고 |
| Loading | 아이보리 10% 투명도 스켈레톤 3개 또는 가운데 스피너 + "불러오는 중이에요" |
| ErrorState | "문제가 생겼어요" + 이유 한 줄 + '다시 시도' 버튼 |
| EmptyState | 국화 마크(작게) + 안내 문구 + 다음 행동 버튼 하나 |

부품이 남색 위에서 보이게 만들어져 있으니, 화면에서 따로 배경색을 칠하지 않는다. 같은 모양을 화면 코드에서 다시 만들지 말고 부품을 가져다 쓴다.

## 6. 움직임
- 저절로 움직이는 것은 **첫 화면의 기한 선이 위에서 아래로 그려지는 한 번**뿐이다. 다른 화면은 들어올 때 움직이지 않는다.
- 사람이 누른 것에 대한 반응은 쓴다: 메뉴 열림, 체크, 진행률 막대가 늘어남(0.3초 이내).
- `prefers-reduced-motion`이면 모두 끈다.

## 7. 문구
- "~해요" 체. 짧게. 위로하는 말은 첫 화면 한 줄 정도만, 나머지는 할 일 중심.
- 버튼은 누르면 일어나는 일을 그대로: "할 일 만들기", "요청서 만들기". 같은 일은 끝까지 같은 이름.
- 오류는 무엇이 잘못됐고 어떻게 하면 되는지 한 줄. 빈 화면은 다음 행동 하나를 권한다.
- 법적 판단처럼 보이는 문장은 피하고 "전문가 확인이 필요해요"로 안내.
