# 제품 명세 (product.md)

담당: 정예준 · 기준 문서: 최종 사업기획안(남김_사업기획안_최종본_1116) 9장
이 문서에 없는 기능은 만들지 않는다. 바꿀 일이 생기면 이 문서를 먼저 고치고 구글 독스 '결정 기록' 탭에 남긴다.

## 1. 서비스 요약
- 이름: 남김
- 한 줄: 장례 이후 유족이 해야 하는 해지, 명의변경, 상속 업무를 한곳에서 처리하게 돕는 모바일 웹 서비스.
- 이용자: 유족(무료). 상조사·보험사 같은 파트너가 이용 가정당 비용을 낸다.
- 시작 경로: 상조사(가상: 하늘상조) 문자 링크 → 휴대폰에서 연다.
- 이번 과제의 목표: 교수님과 청중이 배포 링크로 들어와 구글 로그인 후 처음부터 끝까지 혼자 쓸 수 있는 웹앱.

## 2. 기준 시나리오 (샘플 데이터와 화면 흐름의 기준)
- 박서연(가명), 38세, 서울 거주 직장인, 외동딸. 대구에 혼자 사시던 아버지가 별세. 아버지는 하늘상조 회원.
- 발인 날 하늘상조 문자로 남김을 알고 구글로 로그인 → 질문 5개 답변 → 할 일과 기한(예: 상속포기 D-82) 확인.
- 샘플 조회 결과를 AI로 분석해 놓칠 뻔한 은행·보험·차량을 찾아 할 일로 추가 → 필요한 서류 확인 → 기관별 요청서 PDF.
- 대구 업무는 샘플 행정사에게 맡김 → 다음 날 다른 기기로 로그인해도 진행 상황이 이어짐.
- 하늘상조는 파트너 대시보드에서 이용 현황과 청구 예정액을 본다.

## 3. 8개 기능
1~6번을 먼저 완성하고 7~8번을 만든다. 8개 모두 완성해 공개한다.

### 기능 1. 첫 화면과 구글 로그인
- 하늘상조(가상)의 이름과 로고로 시작한다.
- 시작 전에 알린다: 유족 이용료 무료, 진행 상황은 계정에 저장, 주민번호와 조회 결과 원문은 저장하지 않음, AI 기능 포함.
- 'Google 계정으로 시작하기' → 처음 쓰는 사람은 질문 화면, 답변이 있는 사람은 홈으로.
- 하단에 이용 안내 페이지(AI 사용, 개인정보 처리와 국외 이전 고지) 링크와 파트너용 화면 링크.
- 내 정보 화면에서 로그아웃과 탈퇴(계정과 모든 기록 삭제).

### 기능 2. 질문 5개
- 고인과의 관계, 별세일, 고인의 거주 지역, 상속인 수, 유언장 유무를 한 화면에 하나씩 묻는다.
- 진행 단계(예: 4/5) 표시, 이전으로 돌아가 답 바꾸기, '잘 모르겠어요' 선택 가능.
- 답변은 계정에 저장된다. 나중에 홈에서 답을 고칠 수 있다.

### 기능 3. 홈: 할 일, 기한, 진행률
- 답변을 규칙(`lib/rules.ts`)에 넣어 할 일 목록과 기한을 만든다. 같은 답이면 항상 같은 결과.
- 놓치면 손해가 큰 기한(상속포기·한정승인, 상속세 신고 등)을 별세일 기준 D-day로 맨 위에.
- 답을 바꾸면 할 일과 기한도 바뀐다(예: 유언장이 있으면 '유언장 확인' 추가).
- 끝낸 일을 체크하면 진행률이 오르고, 체크 상태는 계정에 저장된다.

### 기능 4. AI 조회 결과 분석
- 샘플 안심상속 조회 결과를 불러오면 이름과 주민번호를 브라우저에서 가린 뒤 서버로 보낸다.
- AI가 기관명, 종류(은행·보험·통신·자동차·공공), 계좌·계약 건수를 추출해 보여준다.
- 이용자가 확인하면 기관별 할 일로 추가된다.
- 결과에 'AI 생성'과 "원본과 대조해 주세요" 안내를 표시한다.
- 20초 안에 응답이 없거나 형식이 틀리면 미리 검증한 예비 결과를 보여준다. 계정당 하루 5회까지.

### 기능 5. 준비 서류 모아보기
- 할 일 목록에 있는 기관들의 필요 서류를 합쳐 서류별 필요 부수, 발급처, 그 서류가 쓰이는 기관을 보여준다.
- 발급한 서류를 체크하면 계정에 저장된다.
- 조회 결과에 나오지 않는 기관(예: 통신사)은 목록에서 골라 직접 추가할 수 있다.

### 기능 6. 기관별 상세와 요청서
- 기관별 해야 할 일, 필요 서류, 신청 방법을 보여준다.
- 이용자가 입력한 값이 그대로 채워진 요청서를 PDF로 내려받는다(브라우저에서 생성, 한글 글꼴 포함).
- 은행, 보험사, 통신사 각 1곳의 샘플 양식. 개별 판단이 필요한 일에는 '전문가 확인 필요'.

### 기능 7. 행정사 연계
- 맡길 일을 고르고 샘플 행정사 목록에서 지역, 처리 실적, 보수를 비교해 직접 선택한 뒤 신청한다.
- 고지: 남김이 행정사를 배정하지 않으며, 위임계약과 보수 지급은 행정사와 직접 이뤄진다.
- 신청 내역은 계정에 저장되어 '맡기기' 탭에서 확인한다. 샘플이라 실제 행정사에게 전달되지 않는다고 알린다.

### 기능 8. 파트너 대시보드 (PC 화면)
- DB에 쌓인 실제 이용 기록을 집계해 하늘상조 기준으로 보여준다: 이번 달 이용 가정 수, 청구 예정액(이용 가정 수 × 3만 원), 평균 진행률, 정리 완료 가정 수, 최근 14일 신규 이용 추이, 진행 단계별 가정 수.
- 개인을 알아볼 수 있는 정보 없이 집계 수치만 표시한다(DB 집계 함수 `partner_stats`가 숫자만 돌려줌).
- 첫 화면의 파트너용 링크로 연다.

## 4. 만들지 않는 것
- 실제 은행·보험사·정부 기관 연동, 결제, 행정사 실제 연결과 배정, 유품정리 업체 연결, 알림 발송.
- 위 8개 기능에 없는 화면이나 기능.

## 5. 저장하는 것과 저장하지 않는 것
- 저장: 답변, 할 일과 체크 상태, AI가 추출한 기관명·종류·건수, 서류 체크, 행정사 신청 내역, AI 호출 횟수.
- 저장하지 않음: 주민등록번호, 조회 결과 원문, 요청서에 입력한 이름과 연락처.
- 계정마다 자기 기록만 읽고 쓴다(RLS). 탈퇴하면 모든 기록이 함께 지워진다.

## 6. 할 일 기한 참고 (구현 전에 법령을 다시 확인)
- 사망신고: 사망 사실을 안 날부터 1개월 이내
- 상속포기·한정승인: 상속 개시를 안 날부터 3개월 이내
- 상속세 신고: 상속개시일이 속한 달의 말일부터 6개월 이내

## 7. 완료 기준 (모든 기능 공통)
1. 배포 주소에서 동작한다.
2. 휴대폰 화면에서 깨지지 않는다.
3. 로그아웃 후 다른 기기에서 로그인해도 진행 상황이 이어진다.
4. 다른 계정의 기록에는 접근할 수 없다.
5. AI 응답 대기와 실패 상황이 처리되어 있다.
6. 빈칸이나 잘못된 입력에도 멈추지 않는다.
7. 팀원이 아닌 사람이 설명 없이 처음부터 끝까지 쓸 수 있다.

## 부록 A. 할 일 규칙 (`lib/rules.ts`, 강주원)
답변(`specs/api.md`의 answers)을 넣으면 아래 표대로 할 일을 만든다. 같은 답이면 항상 같은 결과. 기한 기준일은 별세일(deathDate)로 본다(실제 법은 '안 날'·'상속개시일' 기준이므로 화면에 "별세일 기준 예상 기한"이라고 표시).

| rule_key | 할 일 제목 | 기관 | 기한 | 만드는 조건 | 전문가 확인 |
|---|---|---|---|---|---|
| death_report | 사망신고 | 고인 주소지 주민센터({region}) | 별세일 + 1개월 | 항상 | 아니오 |
| safe_inheritance | 안심상속 원스톱 서비스 신청 (재산 조회) | 주민센터·정부24 | 없음 ("사망신고 때 함께 신청" 안내) | 항상 | 아니오 |
| renounce_decision | 상속포기·한정승인 여부 결정 | 가정법원 | 별세일 + 3개월 | 항상 | 예 |
| inheritance_tax | 상속세 신고·납부 | 세무서·홈택스 | 별세일이 속한 달의 말일 + 6개월 | 항상 | 예 |
| health_pension | 건강보험·국민연금 정지 확인 | 국민건강보험공단·국민연금공단 | 없음 | 항상 | 아니오 |
| find_will | 유언장 있는지 확인 | 가족 | 없음 | will = unknown | 아니오 |
| will_probate | 유언장 검인 신청 | 가정법원 | 없음 | will = yes | 예 |
| heir_agreement | 상속인끼리 재산 분할 협의 (상속재산분할협의서) | 상속인 | 상속세 신고 기한과 같음 | heirCount = 2, 3, 4+, unknown | 예 |

- AI 분석이나 직접 추가로 생기는 기관별 할 일(source = ai·manual)은 `specs/api.md`의 POST /api/analysis/apply 규칙을 따른다. 자동차는 "자동차 상속 이전등록"(기한: 별세일이 속한 달의 말일 + 6개월).
- 답을 다시 저장하면 규칙 할 일(source = rule)만 다시 만든다. 같은 rule_key의 완료 체크는 유지하고, 조건이 사라진 rule_key는 지운다. ai·manual 할 일은 건드리지 않는다.
- 홈 맨 위 '가장 급한 기한'은 완료되지 않았고 기한이 있는 할 일 중 기한이 가장 가까운 것.
- 위 기한은 구현 전에 법령을 다시 확인한다(K5). 다르면 이 표를 고친다.
- 규칙 할 일의 institution_id(서류 계산에 사용, institutions의 key로 찾음): death_report·safe_inheritance → community_center, renounce_decision·will_probate → family_court, inheritance_tax → tax_office, health_pension → nhis_nps, find_will·heir_agreement → 없음(null).
