## 목표
db.md의 테이블을 SQL 파일로 만들고 Supabase에 실행한다. SQL 파일은 저장소에 남기고, 실행은 Supabase 대시보드 → SQL Editor에서 한다.

## Step 1. `supabase/migrations/001_tables.sql`
- 기준 데이터 4개(institutions, documents, institution_documents, agents)를 먼저, 이용자 기록 7개(profiles, answers, user_tasks, analyses, doc_checks, delegations, ai_usage)를 다음에.
- 칸 이름·자료형·check·유일 조건·`on delete cascade`는 db.md 그대로. user_tasks의 두 유일 조건은 부분 유일 인덱스(`where rule_key is not null` 등).
- SQL Editor에 붙여 실행 → Table Editor에서 11개 표 확인.

## Step 2. `supabase/migrations/002_rls.sql`
- 11개 표 모두 `enable row level security`.
- 이용자 기록: 본인 행만 select/insert/update/delete(`auth.uid() = user_id`, profiles는 `auth.uid() = id`).
- 기준 데이터: `authenticated` select만.
- 확인: Table Editor에서 모든 표에 RLS 켜짐 표시.

## Step 3. `supabase/migrations/003_triggers.sql`
- `handle_new_user()` 함수(`security definer`)와 `auth.users` after insert 트리거 → profiles에 (id, '하늘상조').
- 확인: Authentication → Users → Add user로 테스트 사용자(가짜 이메일)를 만들면 profiles에 행이 생긴다. 확인 후 테스트 사용자 삭제 → profiles 행도 사라지는지(연쇄 삭제) 확인.
