## 목표
묶음1(구글 로그인 K3, 테이블 H2)이 바로 시작되도록 외부 서비스 세 개를 준비한다. **키 값은 단톡방·GitHub에 절대 올리지 않는다.**

## Step 1. Supabase 프로젝트
1. supabase.com 가입 → New project → 이름 `namgim`, 지역 Northeast Asia (Seoul), DB 비밀번호는 본인만 보관.
2. Organization → Team(Members)에서 황겸(H2에서 SQL 실행), 정예준을 초대.
3. Project Settings → API에서 확인할 값: Project URL, anon(public) key, service_role key. (K2에서 전달)
   - 화면에 'Publishable key / Secret key'만 보이면 Legacy API keys 탭의 anon·service_role을 쓰거나, publishable을 anon 자리에, secret을 service_role 자리에 쓴다.

## Step 2. 구글 로그인
1. Supabase → Authentication → Sign In / Providers → Google 화면의 **Callback URL**(`https://<프로젝트>.supabase.co/auth/v1/callback`)을 복사.
2. console.cloud.google.com → 새 프로젝트 `namgim` → OAuth 동의 화면(External, 앱 이름 '남김', 지원 이메일) → 범위는 기본(email, profile, openid)만.
3. 사용자 인증 정보 → OAuth 클라이언트 ID(웹 애플리케이션) → 승인된 리디렉션 URI에 1의 Callback URL → Client ID·Secret을 Supabase Google 제공자에 넣고 Enable.
4. OAuth 동의 화면의 게시 상태를 **'프로덕션으로 푸시'**(테스트 상태면 등록한 사람만 로그인됨 → 교수님이 못 씀).
5. Supabase → Authentication → URL Configuration: Site URL `http://localhost:3000`, Redirect URLs에 `http://localhost:3000/**` 추가. (Vercel 주소는 K2에서 추가)

## Step 3. Anthropic 키
1. console.anthropic.com → API Keys → `namgim` 키 생성. 결제·크레딧은 팀에서 정한 방법대로.
2. Limits에서 월 사용 한도를 낮게 설정(예: 10달러).
