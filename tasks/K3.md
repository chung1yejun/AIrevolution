## 목표
구글로 로그인·로그아웃하고, 로그인 안 한 사람은 보호된 화면에 들어오지 못하게 한다. 버튼 연결은 정예준이 Y7에서 한다.

## Step 1. Supabase 연결 파일
- `npm install @supabase/supabase-js @supabase/ssr`
- `lib/supabase/client.ts`(브라우저용), `lib/supabase/server.ts`(서버용, 쿠키 사용) — Supabase 공식 Next.js(SSR) 안내 방식.
- 키는 `process.env`로만 읽는다.

## Step 2. `lib/auth.ts`
- `signInWithGoogle()`: 브라우저에서 Google 로그인, `redirectTo`는 `${location.origin}/auth/callback`.
- `signOut()`: 로그아웃.
- `getUser()`(서버): 로그인한 사용자 또는 null.
- `requireUser()`(API용): 로그인 안 했으면 `lib/api.ts`의 401 응답을 돌려줄 수 있게.

## Step 3. 로그인 콜백 `app/auth/callback/route.ts`
- 받은 code로 세션을 만든다 → answers에 내 행이 있으면 `/home`, 없으면 `/onboarding`(answers 표가 아직 없거나 오류면 `/onboarding`).
- 실패하면 `/?error=login`으로.

## Step 4. 로그인 보호
- Next.js 16 이상이면 루트에 `proxy.ts`(`export function proxy`), 15 이하면 `middleware.ts`. 버전은 package.json에서 확인.
- 세션 갱신 + 로그인 안 한 사람이 보호된 화면에 오면 `/`로.
- 로그인 없이 열리는 곳: `/`, `/about`, `/partner`, `/auth/callback`, `/dev-ui`, `/api/*`(API는 각자 `requireUser()`로 401), 정적 파일.

## Step 5. 확인
- 확인용 임시 페이지(예: `app/auth/test/page.tsx`, 로그인·로그아웃 버튼)를 만들어 확인한 뒤 **PR 전에 지운다**.
- 로그인 → `/onboarding`으로 이동, Supabase → Authentication → Users에 내 계정. 로그아웃 후 `/home` 접속 → `/`로.
- Vercel 미리보기 주소에서도 로그인되는지 확인(안 되면 K2 Step 5의 Redirect URLs 확인).
